## 4. Le point qui contredit l'hypothèse : les warnings "never tick"

**Verdict : à moitié vrai. L'intention est confirmée, la conclusion "donc inoffensif" est fausse pour une partie précise du lot.**

**Ce qui est confirmé côté "délibéré"**, et il faut le dire clairement, c'est solide :
- `TickFrequency` a pour valeur par défaut `Auto` dans le constructeur (`UserWidget.cpp:98`), donc `Never` est **toujours** écrit à la main et sérialisé.
- Rien ne le force globalement : aucun C++ dans `Plugins/`, aucune ligne dans `Config/*.ini`, aucune classe de base commune.
- 39 widgets au total portent `Never` (30 sous `Content/Widget`, le reste sous `Content/Systems` et `Content/UI_Sys`), soit environ 9 % des widgets, groupés par système (4/4 des widgets QBuilder, 4 QuestSystem, 14 dans HUD/Composition) : une passe ciblée, pas une édition en masse. Un sous-ensemble large partage le même mtime `2026-04-18 21:20`, signature d'un traitement par lot.
- Aucun des widgets concernés n'a d'Event Tick BP actif (le quatrième variant du warning, "blueprint implemented Tick event", n'apparaît nulle part dans le log).

**Ce qui est confirmé côté "pas inoffensif"** :
- **Il n'y a aucun rattrapage runtime.** `UpdateCanTick()` écrit `bool bCanTick = false;` et ne recalcule que pour `Auto`. Ni `PlayAnimation`, ni une invalidation, ni l'enregistrement d'une action latente ne peuvent rallumer le tick. `NativeTick` porte même un `ensureMsgf(TickFrequency != Never)` : le moteur considère qu'un widget `Never` qui ticke est une violation d'invariant.
- **Les animations ne sont pas juste ignorées, elles sont détruites.** `UMGSequenceTickManager` évalue une frame (le flag `bIsTicking` par défaut à `true`), puis bascule à `false`, puis appelle `DisableAnimations()` et retire le widget de sa liste. Le commentaire du moteur note lui-même que les animations "sont encore en cours" à ce moment. Résultat pratique : l'élément peut rester figé sur son état de frame 0, par exemple opacité 0 pour un fade-in, donc **invisible en permanence** plutôt que simplement statique.
- **Le warning "native tick" ne prouve rien à lui seul** (il teste une métadonnée, pas la présence réelle d'un override) : il a fallu lire le C++. Résultat : **2 vrais défauts sur 3**, pas 1.

**Le test de contrôle qui rend tout ça crédible :** la chaîne `CallFunc_PlayAnimation*_ReturnValue` / `K2Node_PlayAnimation` a été cherchée sur les 20 widgets `Never` qui n'ont **pas** de warning d'animation : **0 sur 20**. Ce n'est donc pas du boilerplate hérité des tables d'import, la signature discrimine réellement.

**Ce qui reste non vérifié et qui décide de la sévérité finale :** la première keyframe de chaque animation. Si frame 0 est un état caché (opacité 0, scale 0), le bug n'est pas "l'animation ne joue pas" mais "l'élément reste invisible", ce qui ferait passer ces widgets de "perte de juice" à "élément de HUD manquant". Impossible à lire éditeur fermé.

**Une conséquence pratique importante :** 24 des 27 assets warnés affichent dans l'AssetRegistry un tag `TickFrequency=Auto` alors que leur CDO est `Never` (le tag n'est réécrit que par `UpdateTickabilityStats`, donc une passe qui écrit le CDO sans recompiler le laisse périmé). **Le filtre TickFrequency du Content Browser ment sur ce projet.** Corollaire : ne corrigez pas ça par script Python sur les `.uasset` ; passez par l'éditeur avec recompile, pour que CDO et tag redeviennent cohérents.

Toutes les conclusions ci-dessus s'appuient sur des matchs positifs, sauf indication contraire explicite.
